GI Buddy Production Completion Requirements
Project Background
GI Buddy is a gastrointestinal diet-assistance mobile app that helps users manage GI-related conditions such as IBS through personalized diet recommendations, food analysis, grocery planning, meal planning, and colonoscopy preparation guidance.
The current application has already been built as an MVP/PWA-style version using Flutter frontend and FastAPI backend. The next phase is to convert the MVP into a more production-ready mobile app with stronger infrastructure, payments, admin tools, subscriptions, notifications, app store readiness, and performance improvements.
HIPAA compliance is out of scope.
The app will not store patient names and will use user IDs and high-level diet direction only.

M1 Basic Security + Production Hardening
Requirement Description
The application needs basic security and production hardening before public launch. This does not include HIPAA compliance, but the app still needs standard security practices for a consumer mobile application.
Detailed Requirements
•	Implement HTTPS for all frontend-to-backend communication.
•	Remove hardcoded backend IP addresses from the Flutter app.
•	Move API URLs, keys, and environment values into secure configuration files.
•	Create separate environment configurations for development, staging, and production.
•	Validate Firebase authentication tokens on the backend.
•	Ensure backend APIs are not publicly accessible without proper authentication where required.
•	Remove any plaintext password storage or insecure credential handling.
•	Review local storage usage in Flutter, including SQLite and SharedPreferences.
•	Store only non-sensitive required data locally.
•	Add secure handling for API keys and third-party service credentials.
•	Add request validation for backend endpoints.
•	Add input validation for diet preferences, allergies, conditions, OCR inputs, barcode scans, and chat prompts.
•	Add improved API error handling.
•	Add backend exception handling to prevent raw errors from being exposed to users.
•	Add basic rate limiting to prevent abuse of AI and OCR endpoints.
•	Add structured logging for production debugging.
•	Add basic privacy-aligned handling of user IDs and diet-related data.
•	Add privacy policy and terms links inside the app if required for store submission.
•	Ensure all production secrets are removed from the source code repository.
Out of Scope
•	HIPAA compliance.
•	BAA/vendor compliance review.
•	PHI-specific workflows.
•	HIPAA audit logging.
•	Formal compliance documentation.
•	Medical record integrations.
